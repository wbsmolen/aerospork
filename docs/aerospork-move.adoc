= aerospork-move(1)
include::util/man-attributes.adoc[]
:manname: aerospork-move
// tag::purpose[]
:manpurpose: Move the focused window in a direction
// end::purpose[]

// =========================================================== Synopsis
== Synopsis
[verse]
// tag::synopsis[]
aerospork move [-h|--help] [--window-id <window-id>] [--boundaries <boundary>] [--boundaries-action <boundary-action>] (left|down|up|right)

// end::synopsis[]

// =========================================================== Description
== Description

// tag::body[]
`move left` moves the focused window one place to the left in the tree, and so on for the other directions.
The window swaps places with a neighbor, moves into the container beside it, or moves out of its own container.
The examples show each case.

A floating window moves 50 points in that direction and stops at the edge of its monitor.
At the edge, `--boundaries all-monitors-outer-frame` takes it to the next monitor.

Old spelling, still accepted: `move-through`.

// =========================================================== Options
include::util/conditional-options-header.adoc[]

-h, --help:: Print help and exit.

--window-id <window-id>::
include::util/window-id-flag-desc.adoc[]

--boundaries <boundary>::
Where the edge is. The default is `workspace`.
+
* `workspace`: the edge of the workspace.
* `all-monitors-outer-frame`: the outer edge of all monitors together. At the edge of a monitor inside that frame, the window moves to the next monitor in that direction.

--boundaries-action <boundary-action>::
What happens at the edge. The default is `create-implicit-container`.
+
* `stop`: nothing changes, and the command exits 0.
* `fail`: nothing changes, and the command exits 1.
* `create-implicit-container`: put the other windows of the workspace in a new container, and put the window beside it in that direction. See the last example.

// =========================================================== Arguments
include::util/conditional-arguments-header.adoc[]

(left|down|up|right):: The direction to move the window in.

// =========================================================== Exit status
include::util/exit-status.adoc[]

`move` exits 1 when no window is focused, for a minimized window, a macOS fullscreen window or a window of a hidden app, and at the edge with `--boundaries-action fail`.

// =========================================================== Examples
include::util/conditional-examples-header.adoc[]

. Given this layout
+
----
h_tiles
├── window 1 (focused)
└── window 2
----
+
`move right` gives this layout
+
----
h_tiles
├── window 2
└── window 1 (focused)
----

. Given this layout
+
----
h_tiles
├── window 1
├── window 2 (focused)
└── v_tiles
    ├── window 3
    └── window 4
----
+
`move right` gives this layout
+
----
h_tiles
├── window 1
└── v_tiles
    ├── window 3
    ├── window 2 (focused)
    └── window 4
----

. Given this layout
+
----
h_tiles
├── window 1
└── v_tiles
    ├── window 3
    ├── window 2 (focused)
    └── window 4
----
+
`move left` gives this layout
+
----
h_tiles
├── window 1
├── window 2 (focused)
└── v_tiles
    ├── window 3
    └── window 4
----

. *Implicit container example*
+
Sometimes `move` has to create a container to do what you asked.
+
Given this layout
+
----
h_tiles
├── window 1
├── window 2 (focused)
└── window 3
----
+
`move up` gives this layout
+
----
v_tiles
├── window 2 (focused)
└── h_tiles
    ├── window 1
    └── window 3
----
+
`move` created the `v_tiles` container.
+
With `--boundaries all-monitors-outer-frame` and a monitor above, `move` creates no container.
It moves `window 2` to the monitor above.
