== Synopsis
[verse]
aerospork [-h|--help] [-v|--version] <subcommand> [<args>...]

== Description

The *aerospork* command sends one command to the running AeroSpork app and prints its answer.
The same commands run from bindings and callbacks in the config, without the `aerospork` prefix.

`aerospork --help` lists every subcommand with its purpose.
`aerospork <subcommand> --help` prints the synopsis of one subcommand, and `man aerospork-<subcommand>` describes it.

In this manual, a _node_ is a window or a container in the tree. In practice, the commands move windows.
The _focused_ window, workspace and monitor are the ones that have keyboard focus.
Each monitor shows one _visible_ workspace. A workspace that is not visible is _off screen_.

== Options

-h, --help:: Print the list of subcommands and exit.

-v, --version:: Print the version of the CLI and of the running app, and exit.

== Environment

AEROSPORK_DEBUG_LOG::
When it is set in the environment of AeroSpork.app, the app writes verbose tracing to the unified log, where `log stream` shows it.
See https://aerospork.app/docs/guide.html#troubleshooting[the guide on troubleshooting].

== Files

~/.aerospork.toml, $XDG_CONFIG_HOME/aerospork/aerospork.toml::
The config. AeroSpork reads one of them. See aerospork-config(1).

/tmp/<bundle-id>-<user>.sock::
The socket that the CLI talks to the app through. A release build and a debug build each have their own socket, so the CLI of one build cannot reach the app of the other.

== Diagnostics

`Warning: AeroSpork client/server versions don't match`::
The CLI and the running app come from different builds, usually because AeroSpork updated and the app did not restart.
The command still runs. Quit AeroSpork and open it again.

`Can't connect to AeroSpork server. Is AeroSpork.app running?`::
The CLI cannot reach the app, and exits 3. Open AeroSpork.app, then run the command again.
